# 勘误 · 代码侧口径 · 2026-11-16

起因：核对 `X094` 这一行为什么判 PASS 时，发现表里「代码_词数 203」与 v5 清单里的 260 对不上。
追下去是三件事，都影响已经写进报告的数字。

## 一、代码侧取错了文本

`s2_gate.py` 取代码文本的顺序是 `C_conclusions_clean` → `C_conclusions`。
前者是 **2026-11-15** 为 494 篇交付做的一次清洗，不是 v5 交付的那份（**2026-10-16**）。

| 目录 | 篇数 | 生成时间 | 是什么 |
|---|---|---|---|
| `C_conclusions` | 696 | 11-14 17:09–20:51 | 规则引擎按 `B_spans` 切出来的原始文本 |
| `C_conclusions_clean` | 497 | 11-14 21:01–11-15 14:25 | 在其上做过尾部清洗的版本 |

后果：`代码_词数`、`代码_在窗`、`文本相似度`、`代码_结论段` 四列描述的是**清洗版**，不是 v5。
500 篇与 v5 清单比，**400 篇词数不一致**（357 篇清洗版多于 v5，43 篇少于 v5，多寡都在 ±10 词内，多为破折号展开与断词合并）。

**引用规则**：
- 要 v5 的数字 → 用 `最终语料库_500篇_v5\00_清单.csv` 的 `words` 列。
- 要「模型 vs 规则」的对照 → 用本表的 `文本相似度`，它比的是清洗版，这一点必须写明。
- 不要把 `代码_词数` 当作「规则引擎切出来的结论段有多少词」。

## 二、越界数字要分三层

`boundary_class = code_overshot` 比的是**跨度记录**（`code_end` vs `llm_end`），不是交付文本。
v5 交付文本早被清洗过，所以三层差别很大：

| 口径 | 篇数 | 占老 499 |
|---|---|---|
| 跨度记录越界 | 82（在 v5 里 61） | 12.2% |
| v5 交付文本与模型文本不同（sim < 0.999） | 15 | 3.0% |
| v5 交付文本真的含被排除的尾部原句 | **4** | **0.8%** |

四篇：`X240` +103 词、`226` +59、`X094` +57、`131` +9。
原报告写的「11.8% 的篇目把致谢、附录、Limitations 带进结论段」据此作废，改为 0.8%（4 篇）。

## 三、Excel 打不开 / 提示「已修复」

`汇总表_697篇.xlsx` 在 Excel 标题栏显示「已修复（Repaired）」，原因是 `openpyxl` 把以 `=` 开头的文本单元判成公式：

```
02_删除明细!D4264 = "=tsû"      # 语法例句里的等号
02_删除明细!D4414 = "=khen"     # 同上，X368 那一篇
共 131 个单元
```

Excel 见到无效公式就「修复」文件，把这些单元清掉或改写。

**修法**：写入时把每个文本单元的 `data_type` 强制回 `"s"`（`s5_table.py` 的 `app()`）。
重生成后复查：公式型单元 **131 → 0**，`D4264` 读出 `"=tsû"`、`D4414` 读出 `"=khen"`，七个工作表行列数不变。
