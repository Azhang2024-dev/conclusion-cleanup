## 四、渠道清单

### A 程序化 OA（零成本，可复算）

| 渠道 | 入口 | 门槛 | 给什么 |
|---|---|---|---|
| **OpenAlex** | `api.openalex.org/works?filter=primary_location.source.issn:ISSN,...` | 无 key，加 `mailto=` | `best_oa_location.pdf_url` + `version` |
| **Unpaywall** | `api.unpaywall.org/v2/DOI?email=` | 邮箱 | `url_for_pdf` + `version`（published/accepted/submitted），**判版本唯一可靠来源** |
| **CORE** | `api.core.ac.uk/v3/search/works` | 免费 key | 仓储聚合，接收稿多 |
| **Semantic Scholar** | `api.semanticscholar.org/graph/v1/paper/DOI?fields=openAccessPdf` | 无 key（限速） | 第三条独立线索 |
| **DOAJ** | `doaj.org/api/search/articles` | 无 | 只覆盖全 OA 刊，这 10 刊基本用不上 |
| **OpenAIRE** | `api.openaire.eu/search/publications` | 无 | 欧盟项目产出 |

### D 作者与学术网络

- **邮件索取**：一句模板即可（"compiling a corpus of RA conclusions for a thesis on phrase frames … would you share the accepted manuscript of …"）。
- **ResearchGate / Academia.edu** 的 Request full-text：命中率高于群发邮件。
- **Google Scholar "All versions"**：常能绕开出版社拿到仓储版。

| 渠道 | 入口 | 说明 |

## 五、抓取流水线（已落盘）

`_tools/s51_fetch_oa.py`：

```powershell
# 先看能抓到什么
.venv\Scripts\python.exe 11_语料重建_2026-11\_tools\s51_fetch_oa.py --issn 1475-1585 --limit 20 --dry-run

# 真下，落台账，与现有池子 sha1 去重
.venv\Scripts\python.exe 11_语料重建_2026-11\_tools\s51_fetch_oa.py ^
  --issn 1384-6655 --limit 100 --out "05_语料库\新增_OA" ^
  --pool "05_语料库\人类文本_500篇"
```

脚本里的三条硬规则，都是踩过的坑：

1. **sha1 与 DOI 双去重**：同一篇的排版件与接收稿字节不同，sha1 拦不住（`011`/`103` 就是这么进来的）。
2. **记 `version`**：接收稿的断行与页码完全不同，下游「页眉页脚几何判据」会失效。
3. **PDF 头校验**：防 HTML 登录页冒充 PDF。

实测：脚本对仓储落点一次成功（`ora.ox.ac.uk` 1.29 MB、`ueaeprints` 632 KB），对 `sciencedirect` 403、`wiley` 挂起到 25 s 超时。所以先跑 **IJCL（仓储 57%）、JP（40%）**，出版社为主的三家（TQ 8%、CL 14%、LL 16%）留给浏览器。

## 六、代价与注意事项

- **OA 里混着非研究论文**：书评、编者按、勘误、专辑导言。JS 与 LT 比例最高。
- **上限不是产出**：1,127 个链接是抽样口径，池子 697 → 入册 483（69%），新抓的还要过闸门、250–600 窗、边界、去重、亲读。
- **别把刊分布拉得更歪**：JP 已占 19.5%，补源优先 TQ、LT、JoS。
- **合规面**：A、B 层干净；E、F 层灰，抓到的 PDF 不进任何公开仓库（`.gitignore` 已排除 `*.pdf`）。
