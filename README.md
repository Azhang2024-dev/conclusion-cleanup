# 结论段清理标准与工具（human-conclusion-cleanup）

把「从 PDF 里抽出来的结论段」清洗成可用于语料库的定稿文本，并把每一步留成可复核的台账。
适用于语言学论文结论段语料（本仓以 494 篇英文期刊 RA 结论段为实例）。

**这是标准，不是一次性脚本。** 判据写在 [docs/判据表.md](docs/判据表.md)，阈值写在 `rules.yaml`，脚本只负责执行。

## 三条铁律

1. **只标不删** —— 自动判断只产出「待删清单」，不动正文。
2. **原件只读** —— PDF 与上游文本一律不改，产物写新目录。
3. **每处留证** —— 删了什么、为什么、几个词，全部落 CSV；不写「已清理」这种没有明细的话。

## 一条结论段要过五道关

| 关 | 做什么 | 通过条件 |
|---|---|---|
| 1 定位 | 多路信号扫全文，出候选行号 | 候选必须逐行读过（含前后各一行），不许只看命中数 |
| 2 标红取证 | 在原文本标红，产台账 | 正文字符变化数 = 0 |
| 3 拼接核查 | 逐处读「前一行结尾 + 后一行开头」 | 零处半句、双标点、主谓断裂 |
| 4 应用删除 | 按台账删，保留项跳过 | 删除前验证片段仍在（防行号漂移） |
| 5 重算核验 | 词数、格式、子序列、查重 | 见核验清单 |

## 十三个理由码（封闭集）

`running-head` `pagenum` `caption` `table` `watermark` `tail-block` `heading-trail`
`footnote-call` `pipe` `mojibake` `dup-word` `word-split` `keep`

每个码的判据、反例、处置见判据表。

## 本仓的内容

```
docs/判据表.md          标准本身（13 个码 + 五道关 + 核验清单 + 已知坑）
docs/已定口径.md        三个语料边界决定：后置块不算结论 / 保留外部出处 / 250-600 窗
rules.yaml              阈值与正则（可改，不用改代码）
tools/                  detect / mark / splice_check / apply / verify / report
examples/494篇_验证报告.md   本标准的回归基线：494 篇跑出来的结果
```

## 回归基线

标准改一次，就要在 494 篇上重跑一次，标记结果必须与
`examples/494篇_验证报告.md` 记录的 107 处逐条一致。不一致的地方，就是人工介入点，
必须逐条写明「为什么这次规则不能覆盖」。

## 已知未覆盖

- **硬连字符断词**（`experi-` + `mental`）：约 1675 处，需词典判定，未处理
- **跨行合并修词**（`influe uence` → `influence`）：会让「保序子序列」失效，按特例登记
- **判断依赖 PDF 版式**：换出版社（Elsevier→De Gruyter）需重调阈值，所以阈值外置到 `rules.yaml`
